# 代码结构与职责

lazyclash 当前只有一个可执行程序，入口位于根目录。源码内可直接 `go run .`、`go build .`，构建到指定目录使用 `make build`。Cobra 子命令集中在 `internal/cli`，不为每个子命令创建独立包。

```text
main.go                 Fang 执行、信号与进程退出
internal/
  cli/                  Cobra 命令、参数、输出与父 Shell 集成
  tui/                  页面、布局、焦点与异步任务消息
  app/                  CLI/TUI 共享用例、安装事务和失败恢复
  configuration/        订阅快照、Profile 配方与原子关系索引
  mihomo/               发布解析、下载校验、配置及控制 API
  service/              systemd 用户服务操作
  downloadnet/          下载来源、连接代理及脱敏
  store/                私有目录、原子写入与可取消进程锁
scripts/                显式运行的 Linux、PTY 和端到端验证
```

依赖方向为 `main → cli → app`，默认无子命令时由 CLI 进入 TUI，TUI 也直接调用 `app`。业务用例不依赖 Cobra 或 Bubble Tea，不通过启动自身 CLI 完成工作。

## 应用用例

`app` 按职责拆文件，保留同一个包，避免文件移动演变成多层框架：

- `app.go`：应用依赖、构造与共用锁入口。
- `core.go`：版本解析、安装计划、更新及更新事务恢复。
- `install.go`：首次安装的文件准备、发布、服务注册及提交编排。
- `installation.go`：安装记录、配置代际、文件树和所属关系。
- `recovery.go`：首次安装和配置应用的恢复日志与回滚。
- `profiles.go`：构建并校验 Profile，发布独立运行代际、应用及回滚编排。
- `configuration.go`：Full/Managed 配方、用户覆写、依赖构建及安全的配置状态查询。
- `source.go`：有界订阅下载和与实际 core home 一致的内核校验上下文。
- `runtime.go`：端口检查、启动/停止/重启、API 就绪及节点选择。
- `monitor.go`：有超时的运行采样、活动连接列表与按 ID 关闭；网络采样期间不持有应用锁。
- `rules.go`：读取当前内核的规则，保留匹配顺序，查询前后校验服务及安装身份；不把规则加入高频监控快照。
- `logs.go`：验证归属与当前运行进程后，订阅认证控制 API 的实时日志；持续校验进程身份，取消时关闭流，不启用原始日志落盘。
- `snapshot.go`：供界面和 CLI 使用的运行及安装状态。
- `preferences.go`：引导历史和非敏感偏好。
- `state.go`：绑定安装的运行意图、自启动偏好、操作状态与差异；Stop 优先于配置恢复。
- `mode.go`、`capabilities.go`：模式持久化/动态应用和用户服务能力边界。
- `subscriptions.go`：独立来源添加/刷新/删除，验证依赖配方并提交来源 revision，不隐式应用。
- `removal.go`：验证停止、禁用与所属关系后移除内核，保留用户数据。

## 内核文件与服务注册

`configuration` 保存与服务生命周期无关的配置输入：Subscription 指向按内容摘要寻址的原始快照，Profile 引用来源并保存用户模板和显式覆写；`library.json` 原子提交这些关系。Mihomo 的组合、字段所有权和引用语义由 `mihomo` 包实现，`app` 编排构建、内核校验与运行代际提交。运行 generation 固定配方和来源 SHA，来源刷新或用户编辑不会改变已应用配置。竞品源码证据与方案比较见 [订阅与配置调研](subscription-research.md)，领域模型、操作状态变化和扩展边界见 [配置设计](subscription-design.md)，本次执行结果见 [验证记录](subscription-verification.md)。

首次安装分为文件准备、发布和服务注册。文件准备生成默认配置并完成 Mihomo 验证，不操作服务；应用用例在同一个进程锁和恢复日志保护下发布文件，再注册指向已发布路径的服务，最后提交安装记录。注册失败或取消时执行所属关系检查与恢复，不删除用户后来修改的文件。更新继续使用原子部署，保持旧运行进程和配置。

服务适配层负责服务管理器的操作与定义验证。端口冲突、Mihomo 配置验证、API 就绪、引导历史及跨步骤回滚保留在应用层。服务处于 active 状态不能代替控制 API 就绪。

运行监控由应用用例提供一次有界采样，TUI 负责可见页面的调度和取消，CLI 使用同一用例输出单次 JSON。各数据源分别报告不可用；显示内存跳过 Mihomo 的人工首帧零，累计值取内核计数，不在界面层积分或落盘。连接关闭在应用锁内验证服务归属、精确连接 ID 和当前活动列表，仅请求关闭这一条，不提供空 ID 或关闭全部入口。

日志通过同一个 `app.StreamLogs` 用例提供给 CLI 和 TUI；Mihomo 客户端负责有界 NDJSON 帧、类型校验、终端控制符清理和凭据脱敏。TUI 仅保留当前会话最近 200 条，通信队列有界；暂停、离页、打开帮助或向导时断开，恢复明确标记未收集期间的缺口。CLI 使用显式条数和时间窗口收集 JSON。它们都是实时观察，不伪造历史、补采或内核原始时间。

导航顺序与数字快捷键共享同一张七页表。侧栏和活动列表采用各自的焦点组，方向键在组内移动；表单仍按控件切换。界面布局、命中区域和滚动范围从终端字符尺寸计算，缩放不重启业务任务。页面帮助是独立可滚动层，捕获输入并保留底层页面状态。

当前仅维护 `lazyclash-mihomo.service` 的 systemd 用户服务实现，不自动启动、enable、修改 linger 或提权。没有其他平台或 init 系统的占位实现。

后续增加真实平台需求时，通过已有应用层服务接口接入并验证相应适配器，优先评估现有库；不把第三方库类型暴露给 CLI/TUI。平台的权限、用户/系统服务范围及注销后的生命周期需要单独验证，不能由统一接口推断支持。当前不依赖尚未完成的 unisvc，也不使用平级目录的永久 `replace`。

持久生命周期、用户/实际/操作状态与恢复策略见 [持久运行](runtime-lifecycle.md)，权限方案比较及扩展条件见 [权限边界](permissions.md)。当前没有常驻 daemon、特权 helper 或系统级 backend；未来新增平台扩展 service，新增内核扩展 mihomo 适配边界，根据真实差异调整应用接口，不预先创建空实现。
