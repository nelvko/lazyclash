# TUI 通知

全局 Toast 固定从页头右侧开始，不随输入框向下移动、不改变正文高度或滚动位置。宽屏最多展开两条，旧消息在上、新消息在下；窄屏或矮屏最多一条，采用无边框紧凑布局。布局同时检查可用高度和输入区域，不能完整展示说明时保留“另有 N 条 · 展开”入口，不无限堆叠或把旧消息自动压成一行。

底部只保留终端最后一行的按键提示，旧状态栏的空行归还正文。正文、滚动指示和侧栏可使用倒数第二行；紧凑导航展开时同步覆盖这一行并阻止点击穿透。

通知包含消息类型、来源页面、操作上下文和完整的用户说明。较长的操作上下文可在详情中查看；长技术错误使用简短失败说明，并通过详情保留完整原因和恢复信息。通知正文使用普通文字色，标题和边框使用类型颜色，无色模式保留类型文字。

## 操作与保留

- 同一操作的进度和结果更新同一条通知。不同操作分别保存，即使错误文字相同也不合并、不添加重复次数。
- 重试通过操作和资源标识关联原失败；资源标识内部使用摘要，来源 URL 或凭据不作为展示上下文。
- 成功展开后显示 3 秒，普通信息显示 4 秒；错误保留至手动关闭，切页仍保留原来源。通知在溢出区、弹窗、帮助、菜单或通知列表中时暂停自动关闭计时。进入可见浮层后从剩余时长继续；新的结果重新计时，旧定时器不影响新结果。
- 关闭进行中通知只隐藏它，不取消任务；最终结果仍可以出现。取消任务保留原有 Esc/Ctrl+C 行为，普通取消是信息，伴随清理或恢复失败时仍是错误。
- 后台 runtime、rules 和 logs 采样错误保留在各自页面，不为每次轮询创建全局 Toast。
- 操作后的状态回读失败时，页面保留配置库等已有数据，但运行状态显示未知，不把上次观察到的实际模式和节点作为当前事实。后续有效状态观察恢复展示。无关成功不会删除其他操作的错误通知。
- 安装或端口应用弹窗中的恢复失败、最终状态回读失败同时保留一条全局错误，关闭弹窗后仍可查看；弹窗内的普通校验不生成全局通知。重试成功后更新原错误。端口已经提交但回读失败时仍明确保留“已应用”的结果，运行状态显示未知。

## 列表、详情与输入

点击“另有 N 条 · 展开”或按 `Ctrl+N` 打开有边界的通知列表，使用 Charm Bubbles viewport 滚动完整说明；`↑↓` 选择通知，`Enter` 打开详情，`x` 关闭指定通知，`PgUp/PgDn` 滚动，`Esc` 从详情返回列表或收起列表。操作按钮也支持鼠标和 Tab。输入框编辑期间保持其原有按键语义，可先 Esc 离开编辑再打开通知列表。

通知不会抢焦点。Esc 优先处理输入、菜单、帮助和弹窗；没有这些交互时才关闭通知。通知覆盖的单元格不接受底层按钮点击或滚轮事件。列表收起后恢复原焦点。

订阅地址为空、格式不正确等局部校验紧贴 Profiles 输入框显示，保留输入，修改或离页后清除。来源和地址编辑弹窗在提交前校验，错误继续留在弹窗中。下载、校验和保存等异步失败进入全局通知，切换页面后仍可查看原因。不会为了自动关闭 Toast 而给所有页面添加重复错误面板。

验证入口见 [verification.md](verification.md)，真实终端场景由 `scripts/theme-pty.py` 的通知检查覆盖。
