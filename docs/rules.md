# 规则管理

在 TUI 中按 `5` 或选择侧栏的 Rules，查看当前 Mihomo 加载的规则。列表来自控制 API，保留原始匹配顺序和位置；不会用磁盘上的订阅或旧列表代替当前结果。

主列表显示内核实际生效的规则，保持只读。Rule 模式按规则顺序匹配；Direct、Global 模式不会因为打开此页而切换为 Rule 模式。页头的「规则集合」用于查看和更新提供器，「自定义规则」用于编辑当前 Profile 的独立覆盖规则。

## 布局与筛选

规则采用双行列表：左侧序号独立对齐，第一行突出匹配条件，第二行显示规则类型与目标策略。长条件截断后可按 Enter 在列表原位展开完整内容；禁用状态保留在第二行。`MATCH` 在列表中显示「所有剩余流量」，内核返回的空条件仍保持原样。

焦点在侧栏或其他控件时，选中项保留覆盖两行的蓝色竖条；焦点进入规则时改为首行黄色箭头。鼠标悬浮只改变背景，不改变规则选择。

筛选栏固定在列表上方，滚动规则时仍可操作。宽窗口把输入与选项放在同一行，窄窗口拆为两行；极短窗口将筛选栏并入可滚动正文。摘要显示匹配数与总数，规则保持内核原始顺序，筛选不改变优先级。

滚轮只移动视口，不改变键盘选择；滚动后的高亮按指针当前位置重新定位。lazyclash 不叠加滚动动画或惯性，按终端传入的离散滚轮事件移动。

- `Aa` / `Alt+C`：区分大小写，默认关闭。
- `ab` / `Alt+W`：整词匹配；Unicode 字母、数字及下划线视为词内字符。
- `.*` / `Alt+R`：正则表达式，默认关闭。无效表达式会显示错误并隐藏结果，修正后立即恢复。
- `×`：清空筛选文字，保留匹配选项并返回输入框。

三个匹配选项可组合使用，对类型、条件、目标、显示序号（如 `#1`）和 API 索引（如 `index:0`）分别匹配，不跨字段拼接。整词模式也对正则匹配结果检查词边界。鼠标悬浮或键盘聚焦选项时，摘要显示该选项说明。

## 操作

- `/` 或点击筛选框：输入筛选条件，默认按大小写不敏感的字面子串匹配。
- `Enter`：结束搜索并选中匹配项，再按一次原位展开或收起。
- `↑/↓` 或 `j/k`：选择规则；长列表自动保持当前选中项可见。
- `Tab / Shift+Tab`：切换焦点；输入中按 Tab 可到匹配选项。鼠标点击规则任一内容行只选中并定位该规则，留在列表；按 `Enter` 原位展开完整条件与统计。滚轮、`PgUp/PgDn` 可滚动列表。
- `Esc`：退出搜索或收起展开内容；未展开时返回导航；`q` 退出应用，搜索输入中的 `q` 和数字正常输入。
- `g` / `Ctrl+R` 或失败时的 Retry：重新读取。`r` 保留原有的服务重启含义。

页面顺序与快捷键统一为 `1 Overview`、`2 Proxies`、`3 Profiles`、`4 Connections`、`5 Rules`、`6 Logs`、`7 Settings`。窄窗口通过 Menu 导航，展开后的长规则条件和中文内容会换行。窗口缩放只影响布局，不重置搜索或重新发起请求。

## 数据与状态

显示位置、类型、匹配条件和目标；序号和搜索保留内核返回的原始位置。`MATCH` 的空条件是合法值，不补造匹配条件。记录数为 `-1` 时表示不适用，不能显示成零；其他非负值如实展示。内核提供可选统计时，可原位展开查看禁用状态及命中/未命中次数；没有这些字段时不伪造统计。

规则集提供器在主列表中保留内核返回的引用，不展开规则文件。内核命中统计的生命周期由 Mihomo 决定，lazyclash 不额外落盘。

页面不提供独立详情页或常驻刷新按钮；Ctrl+R / g 可主动重新读取，失败时显示重试入口。

页面可见时首次异步加载，之后每轮结束五秒再检查一次，避免每秒请求较大的规则列表。离开页面、打开向导、执行操作或退出会取消请求；迟到响应不会覆盖新状态。查询前后检查服务归属、状态、进程和安装身份，跨停止或重启的旧结果会丢弃。

未安装、停止、正在加载、API 不可用、有效空列表和搜索无匹配分别展示。失败时可重试，旧规则不会继续标为当前可用。

## 规则集合

页头「规则集合」读取 Mihomo 的 `GET /providers/rules`，展示名称、来源类型、匹配类型、格式、规则数和更新时间。`/` 可搜索名称或元数据，`↑/↓` 选择；单项更新按钮或 `u` 更新当前集合，页头「更新全部」同时最多执行三个请求。每项分别显示排队、更新中、成功或失败，失败项可独立重试；更新后重新读取元数据。

HTTP 集合使用 `PUT /providers/rules/{name}` 更新；File 集合使用同一 API 重新加载本地文件，Inline 无外部来源，不提供更新且不参与更新全部。批量更新针对全部可更新集合，不限于搜索结果。`g` / `Ctrl+R` 只重新读取列表，`Esc` 返回规则主列表。离开视图会取消排队及在途请求，重入先观察当前内核，不向缓存中的旧集合发起更新。

## 自定义规则

当前已应用的已保存 Profile 可通过「自定义规则」编辑；内置 `default` 不可编辑。编辑区只管理该 Profile 的 `overrides.prepend-rules`，按列表顺序插在订阅规则之前；订阅原文保持独立，更新订阅不会移除这些规则。已有 `set` 和 `append-rules` 覆盖会保留；若 `set.rules` 接管了完整规则列表，先移除此接管再使用编辑器。

每条规则使用完整 Mihomo 语法，例如 `DOMAIN-SUFFIX,example.com,DIRECT`。支持复杂条件，无逗号拆分重写。`a` 新增，`e` 或选中行按 Enter 编辑，`d` / Delete 删除并确认，`Alt+↑/↓` 调整优先级；也可点击工具栏。新增与编辑先按「完成」写入内存草稿。

「保存」或 `Ctrl+S` 校验并原子持久化独立覆盖，不修改运行中的规则。已安装 Mihomo 时同时执行内核配置校验；未安装时只校验配置结构，应用前仍需通过内核校验。「应用」只接受已经保存的版本，确认后按现有配置事务生效；内核运行中会重启服务并中断现有连接，失败沿用原有回滚机制。其他 Profile 设置的待应用变化也会一起应用。

订阅刷新或其他会话修改了 Profile 时，保存/应用会拒绝旧版本并保留当前草稿，需重新加载后编辑。应用前还检查当前已应用 Profile，避免将草稿应用到另一个 Profile。切换其他页面保留草稿；返回主规则列表、重新加载或退出时若存在未保存变化，会先确认丢弃。`Esc` 关闭输入或返回，输入中的字母、数字不会触发全局操作。

## CLI

```sh
lazyclash rules
```

输出按内核顺序排列的 JSON 数组。有效空列表输出 `[]`；内核未安装、未运行或查询失败时返回错误和非零退出码。CLI 与 TUI 主列表使用同一个只读用例；上述管理操作目前由 TUI 提供。
