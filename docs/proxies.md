# 代理组与节点

TUI 中按 `2` 或选择 Proxies，浏览当前 Mihomo 控制 API 返回的代理组及成员。页面不展示代理组总数，不提供手动刷新。应用配置、切换模式或选择节点后，主列表会自动读取最新状态。组头左侧显示名称及当前最终节点，右侧依次显示策略组类型、右对齐的成员总数和折叠箭头。成员数直接显示为数字，与组头共用底色。

在至少 115 列且超过 24 行的终端中，组头文字上下各有一行留白。鼠标悬停时三行一起高亮，点击任意一行都能展开或折叠。展开后组名保持原位。真彩色或 256 色终端的首排卡片紧接组头。低色和无色终端在组头与首排之间保留一行间隔。较窄或较矮的终端使用紧凑组头，在展开组的最后一排成员后保留一行组间隔。

节点卡片的文字占两行，第一行显示名称和延迟，第二行显示协议、UDP 支持或引用摘要。终端至少 115 列、超过 24 行且支持真彩色或 256 色时，两排卡片之间留半行间隔。相同尺寸的低色和无色终端使用两行卡片，排间空一行。窄屏和矮窗都使用连续的两行卡片。名称与元数据左对齐，左侧两格用于选中和焦点标记。延迟靠右对齐，距卡片右缘一格。引用卡片的元数据行显示「策略组 · 最终节点」，并保留独立的「进入 →」。展开含多个匹配成员的组时，可以直接从组头选择排序。可测速的组在同一行显示「测速」，运行时原位显示取消操作与完成数。紧凑目录在正文至少 60 列时每组单行，更窄时两行，条目之间不额外留白。只读取与选择有关的元数据，不展示节点服务器、密码或其他原始配置字段。

正文使用全部可用宽度，节点列数随实际内容宽度变化，最多四列；只有一、两个成员时，卡片仍占对应列宽，不拉伸填满整行。节点布局统一从正文宽度中减去网格缩进（宽屏两列字符、窄屏零列）后，按最小卡片宽度 29 格和一格列间距计算。150 列终端可显示四列节点，80 列终端的成员页可显示两列。各卡片等宽，整除产生的少量余量留在行末。页头右侧的规则、全局、直连构成三个连续等宽的分段，每段可独立点击或通过键盘聚焦。模式控件与「搜索」「代理集合」之间相隔四格。在同一窗口中切换模式时，三个分段和代理集合保持原位，直连模式隐藏搜索入口。空间不足时，控件移到标题下方。少于 50 列时，模式分段固定在可滚动列表、组名和搜索框上方，按完整选项换行。宽窗口允许多个组独立展开，点击组头或按 Enter 可在原位展开。「全部收起」在有组展开时显示在页标题旁。小于 115 列的终端采用「代理组目录 → 组内成员」两级浏览，并在成员页保留组名。窗口尺寸变化时直接重新计算网格，保留排序、展开组和节点身份，并滚动到焦点卡片所在的新行。暂不提供手动列数设置。名称过长时以省略号截断，搜索仍按原始名称匹配。

组内成员连续滚动，不采用分页。当部分成员位于屏幕外时，底部按卡片的可见文字行计算范围。例如「组内成员 1–12 / 48」表示当前可见该组的前 12 个成员。多个展开组都有匹配成员时，按列表顺序合并计数。例如一个组有 1 个匹配成员，另一个有 48 个，前 29 个可见时显示「跨 2 组 · 1–29 / 49」。宽度不足时仅显示数字范围，全部成员均可见时隐藏。切换排序后按成员身份保留焦点。按 `→`、跟随引用或在窄屏进入成员页时，优先把焦点定位到内核当前选择的节点；没有当前项或当前项被筛选隐藏时定位首个匹配成员。宽屏滚动时，只有组头已离开视野且该组仍有节点文字可见，才在页头下方显示吸顶组名。组名利用已有的页头空间，列表位置和滚动高度保持稳定。

按 `/` 或点击页头「搜索」会展开并聚焦单行输入框。搜索忽略大小写，按字面匹配组名、组类型、节点名及协议。组类型可用界面名称、YAML 的 `type` 或控制 API 的类型名搜索，例如「自动选择」、`url-test` 或 `URLTest`。组名或类型命中时保留组内全部成员，仅成员命中时展示匹配项。宽屏临时展开匹配组，窄屏先列出匹配组，再进入查看成员。搜索框在空间足够时固定，极矮窗口随正文滚动。直连模式隐藏搜索入口。

## 操作

- `Enter` 展开或折叠组，或改选焦点所在 Selector 的非当前成员。点击 Selector 成员卡片也可改选。点击自动组的成员卡片仅移动焦点。底栏随焦点、搜索和测速状态显示当前可用操作；同组测试中提示取消，其他可测速组仍提示开始测试。
- `/` 或页头「搜索」：打开并聚焦搜索。输入后按 Enter 聚焦第一条结果，点击框内 `x` 清空查询并继续输入。输入中或浏览结果时按 Esc 结束搜索，恢复打开搜索前的视图、展开组、焦点和滚动位置。输入中的普通字符不会触发切页、退出、测速或服务操作。
- `↑/↓` 或 `j/k`：移动焦点；`Home/End` 到首尾。多列成员中的上下移动保持所在列，滚轮、`PgUp/PgDn` 滚动正文。
- `→` 或 `l` 在多列中先移至同一行右侧的相邻节点。到达右侧边界后，引用组节点可继续进入目标组。在组标题上可进入成员列表。引用组卡片的「进入 →」可直接打开目标组。
- `Esc` 从引用组或窄窗口成员页逐级返回，再返回应用导航。`←` 或 `h` 在多列中先移至同一行左侧的相邻节点，其余情况执行返回。宽屏进入引用组时保留组列表并就地跳转，窄屏进入独立成员页。返回引用来源时恢复原展开组集合、焦点与滚动位置。
- `s`：为焦点所在组选择默认顺序、延迟、名称，各组分别保留排序。默认顺序使用内核成员顺序。展开组的「排序」入口与快捷键打开同一个菜单，应用后在组头显示「延迟 ↑」或「名称 ↑」。组目录按名称排序，不宣称恢复原配置文件顺序。
- `t` 或组头的「测速」：测试当前组的可测试成员；再次按 `t` 或点击本组的取消操作结束本轮，保留已经完成的结果。点击另一组「测速」会取消旧轮并测试目标组；同一时间只运行一组。折叠组或「全部收起」不会取消测速。
- 点击卡片右侧的延迟数值或状态仅为该节点重新测速，结果在原位更新。延迟区域获得焦点后，按 `Enter` 也可测速。不适用的 `—` 区域不响应操作。
- `Tab/Shift+Tab`：在应用导航、页头、页面控件和列表之间移动。列表作为一个焦点组，成员不逐项占用 Tab 停靠点。

普通节点的卡面比页面底色略亮，内核已确认的节点使用蓝色卡面，左侧的蓝色竖条占半个字符宽，上下与卡面齐平。`›` 单独标出键盘焦点。名称、元数据及卡片内侧留白均可点击。点击延迟启动单节点测速，点击引用卡片的「进入 →」浏览目标组。延迟数值和状态在首行右侧对齐，悬停或聚焦时以局部背景标出测速区域。测得的延迟低于 150 ms 时显示绿色，达到 150 ms 时显示黄色。「失败」和「超时」以次要文字显示，进行中的测试使用强调色。测试中和等待中不显示局部背景强调；超时或失败后仍可点击重测。切换期间保留原选择，目标项标为切换中；重新读取控制 API 确认后再显示新选择。失败或不能确认时不报告成功。

## 组语义与路由模式

组头使用 Mihomo 文档中的类型名，鼠标悬停在名称上可查看 YAML 中的 `type` 值。链式代理的悬停提示同时说明该类型已弃用。见 [Mihomo 代理组配置](https://wiki.metacubex.one/config/proxy-groups/) 和 [链式代理说明](https://wiki.metacubex.one/config/proxy-groups/relay/)。

| 组头类型 | YAML `type` | 成员选择 |
| --- | --- | --- |
| 手动选择 | `select` | 可点击成员或按 Enter 改选 |
| 自动选择 | `url-test` | 卡片标记内核选中的成员 |
| 自动回退 | `fallback` | 卡片标记内核选中的成员 |
| 负载均衡 | `load-balance` | 由内核分配流量 |
| 链式代理 | `relay` | 由内核沿代理链转发 |

DIRECT、REJECT 是普通有效候选项，REJECT 不作为界面操作错误标红。

组头摘要优先显示按当前选择解析到的最终节点，例如 `HK 02`。负载均衡、Relay 或无法确定当前项时，摘要显示可解析到的组。连接的实际链路可在 Connections 中查看。

模式控件高亮已保存的路由模式。内核报告的实际模式与其不一致时，正文显示实际模式，并按实际模式展示代理组。Global 模式首先展示 GLOBAL，可继续进入它引用的组；宽屏浏览时将当前引用目标补充显示在同一列表中，窄屏只显示目标组。Rule 模式显示其他代理组，宽屏进入引用组时仍保留普通组列表。内核确认 Direct 模式后，隐藏策略组、节点及其排序、测速、收起和返回操作。正文只显示「所有流量均直接连接。」（英文为「All traffic connects directly.」），在正文可用区域内水平、垂直居中。窄屏模式控件和实际模式诊断仍保留在上方，顶部模式切换和代理集合继续可用。组选择不会被修改，在同一配置与内核实例中切回进入 Direct 前的 Rule 或 Global 模式时恢复展开组、排序和浏览位置；切到另一模式或配置/实例发生变化时按原有规则重置。实际模式未知、不一致或读取失败时仍保留诊断，以内核实际模式决定是否显示列表。

## 延迟测试

测速使用受管的本机认证控制 API，让 Mihomo 通过指定候选项访问固定测试目标。默认目标为 `https://www.gstatic.com/generate_204`，单次超时为 5 秒。每轮仅测试当前组，最多同时发起 4 项；不是整份配置的全量测试。DIRECT、REJECT、LoadBalance、Relay 以及无法确定单一出站的引用路径不生成虚构延迟。

单节点重测另有最多 4 项同时运行的队列，可与一组测速并行。重复点击正在等待或测试的同一节点会复用请求；如果该节点已在本组测速队列中，则优先安排已有请求，不重复发起。开始一轮组测速会取消该组的单节点重测，其他组的单节点重测继续。单节点重测只显示卡片内的等待或测试状态，不占用组进度。

延迟区分未测试、等待中、测试中、数值、超时、测试失败与不适用。卡片以 `—` 表示不适用。普通节点可显示已有内核历史样本。引用组只展示本次会话中记录了选择路径的测试结果，路径变化后恢复为未测试。某个测试目标失败不能证明节点整体离线。

组测速的完成数和总数直接显示在组头，完成或取消后就地短暂提示结果。测速完成只更新结果，不自动重排候选项。需要重新排序时再次选择延迟排序；已有焦点和选择按成员身份保留。离开页面、执行会改变运行状态的操作或退出时取消正在进行的测试，不延续进度提示；迟到结果不会覆盖新一轮。结果保留在当前会话内存，不额外保存至配置或磁盘。

## 不可用状态

未安装、内核停止、API 不可用、没有代理组和有效空组分别显示。未安装或停止提供相应安装、启动入口；API 错误保留诊断。旧数据不会继续作为可操作的实时列表。

## 代理集合

页头「代理集合 / Proxy providers」展示当前内核加载的 Provider。它与规则页「规则集合」共用 `provider_panel.go` / `provider_panel_view.go` 的状态、更新队列和 Bubbles 输入、viewport 组件，只有读取接口和条目元数据不同。代理集合显示名称、来源类型、节点数量及更新时间；未提供更新时间显示未知，不展示原始节点配置、下载地址或认证字段。

HTTP 集合可更新，File 集合可重新读取；Inline、Compatible 及未知来源只读，也不参与批量更新。「更新全部」最多并发三项，失败可单独重试，关闭面板取消排队与在途请求。面板内保留名称或来源类型搜索、独立滚动和固定操作区；集合管理与代理主列表使用各自的搜索框。规则页原有集合操作沿用同一组件。

集合面板的按键提示按当前焦点和可用性显示：只有可更新且未排队/执行中的条目提示 `u`，聚焦更新按钮才提示对应的 Enter 操作；只读条目不提示更新。输入搜索时提示 Enter 查看结果、Esc 结束搜索，输入中的 `u`、`q` 仍是文字。窄屏按完整提示项裁剪，不截断半个按键说明。

更新通过内核的 `GET /providers/proxies` 与 `PUT /providers/proxies/{name}` 执行，不编辑 Profile、运行 YAML 或服务。完成后自动读取完整快照，使代理组和节点同步；部分更新完成后关闭面板、取消或不确定的失败也重新观察当前内核。类型、请求、Profile、generation 和 PID 的旧结果不能写回新面板或新实例。后端请求不持有应用文件锁，慢下载不阻塞停止服务。接口对应 [Mihomo Provider 路由](https://github.com/MetaCubeX/mihomo/blob/Meta/hub/route/provider.go)。

CLI 的 `nodes`、`select` 继续使用共享应用与 API 用例。TUI 不启动 CLI 子进程，也不改变服务安装或 TUN 的权限边界。
