# 代理组与节点

TUI 中按 `2` 或选择 Proxies，浏览当前 Mihomo 控制 API 返回的代理组及成员。页面不展示代理组总数，不提供手动刷新或搜索；应用配置、切换模式或选择节点后自动读取最新状态。分组列表以组头内部留白区分组块：终端至少 100 列、24 行时，相邻组之间不额外插入空行；窄屏或短窗口保留一行组间隔，不绘制横向分隔线。组头显示名称、当前最终节点和右对齐的纯数字成员数徽标；自动策略组保留低强调的「自动」标记，折叠箭头放在成员数右侧，名称前只保留键盘焦点标记。正常高度的宽窗口中，组头上下各留一行，整块区域可以点击和悬浮高亮；短窗口使用紧凑组头。完整类型与引用路径在详情中查看。

展开后只保留组头和节点卡片，不重复显示「当前选择」，默认排序也不单独占行。正常宽窗口的组头与第一排卡片之间不额外插入空行，窄屏和短窗口保留一行间隔；卡片共三行，依次为顶部留白、名称、元数据；相邻节点排之间空一行，名称与元数据左对齐，延迟和「进入」操作右侧保留两格留白。卡片展示候选项、节点协议、UDP 支持和延迟；引用卡片的第二行内容统一显示「策略组 · 最终节点」，并保留独立的「进入 →」。测速操作放在展开组的标题行，空间不足时换行。只读取与选择有关的元数据，不展示节点服务器、密码或其他原始配置字段。

正文使用全部可用宽度，节点列数随实际内容宽度变化，最多四列；只有一、两个成员时，卡片仍占对应列宽，不拉伸填满整行。节点布局统一从正文宽度中减去网格缩进（宽屏两列字符、窄屏零列）后，按最小卡片宽度 36 列、列间隔 1 列计算，最多四列；小于 100 列的成员页也按实际空间排列，80 列终端可显示两列节点。各卡片等宽，整除产生的少量余量留在行末。卡片保留紧凑的行列间隔。页头从左到右排列规则、全局、直连三个模式选项，右侧为「代理集合」；空间不足时控件使用标题下方的一行，少于 50 列时模式选项保留在正文顶部并按宽度换行。宽窗口允许多个组独立展开，打开另一组不会收起已有组；列表上方提供「全部收起」。小于 100 列的终端采用「代理组目录 → 组内成员」两级浏览。窗口尺寸变化时直接重新计算网格，保留排序、展开组和节点身份，并滚动到焦点卡片所在的新行。暂不提供手动列数设置。长名称在列表内截断，详情显示完整名称；不依赖旗帜或颜色识别节点。

组内成员连续滚动，不采用分页。可见范围提示 `1–12 / 48` 表示当前视口内的成员范围与总数；多组展开时按页面中的全部展开成员计算，切换排序后仍以成员身份保留焦点。

## 操作

- `Enter`：展开或折叠组。在 Selector 的成员上按 Enter 改选；在自动组成员上查看详情。
- `↑/↓` 或 `j/k`：移动焦点；`Home/End` 到首尾。多列成员中的上下移动保持所在列，滚轮、`PgUp/PgDn` 滚动正文。
- `→` 或 `l`：在多列中先移至同一行右侧的相邻节点；到达右侧边界后，引用组节点可继续进入目标组。在组标题上进入成员。引用组卡片另有「进入 →」入口，可以直接进入；Enter 激活卡片主体仍执行选择或查看详情。
- `Esc`：从详情、引用组或窄窗口成员页逐级返回，再返回应用导航。`←` 或 `h` 在多列中先移至同一行左侧的相邻节点，其余情况执行返回。宽屏进入引用组时保留组列表并就地跳转；窄屏进入独立成员页。返回引用来源时恢复原展开组集合、焦点与滚动位置。
- `i`：查看成员完整名称、类型、当前选择路径及可用的测试详情。
- `s`：为焦点所在组选择默认顺序、延迟、名称，各组分别保留排序。默认顺序保留内核成员顺序，不额外显示排序行；使用非默认排序时，组头显示对应排序入口。组目录按名称排序，不宣称恢复原配置文件顺序。
- `t` 或组头的「测速」：测试当前组的可测试成员；再次按 `t` 或本组「取消测速」取消本轮，保留已经完成的结果。点击另一组「测速」会取消旧轮并测试目标组；同一时间只运行一组。折叠组或「全部收起」不会取消测速。
- 点击卡片右侧的延迟数值或状态：只为该节点重新测速，完成后更新结果，不改变选中节点、排序或展开组。延迟区域获得焦点后，按 `Enter` 可再次测速；卡片主体仍执行选择或查看详情。不适用的 `—` 区域不响应操作。
- `Tab/Shift+Tab`：在应用导航、页头、页面控件和列表之间移动。列表作为一个焦点组，成员不逐项占用 Tab 停靠点。

节点卡片左侧的选中竖条贯穿卡片全高，表示内核已确认的当前项，`›` 表示键盘焦点，两者独立显示。卡片顶部留白和元数据行的右侧留白也可以点击选择；延迟和引用卡片的「进入 →」分别独立处理测速与浏览操作。延迟数值和状态在右侧固定宽度的区域内居中，与节点名称同处卡片中间一行；统一不加下划线，悬浮或聚焦时仅用局部背景变化提示可点击，保留原有状态颜色。测试中和等待中不显示局部背景强调；超时或失败后仍可点击重测。切换期间保留原选择，目标项标为切换中；重新读取控制 API 确认后再显示新选择。失败或不能确认时不报告成功。

## 组语义与路由模式

Selector 允许手动改选。URLTest、Fallback 等自动组由内核选择；成员可查看详情，但不能在这里手动应用。LoadBalance 和 Relay 由内核按自身策略处理，不展示虚构的固定单一节点。DIRECT、REJECT 是普通有效候选项，REJECT 不作为界面操作错误标红。

组头摘要优先显示按当前选择解析到的最终节点，例如 `HK 02`，不重复展示完整引用链。详情中的 `默认代理 → 自动选择 → HK 02` 是按代理组当前选择展开的路径，不代表每条连接实际采用的完整链路。负载均衡、Relay 或没有可确定当前项时停止展开；连接的实际链路应在 Connections 中查看。

模式控件显示内核实际模式，并通过共享应用用例修改。Global 模式首先展示 GLOBAL，可继续进入它引用的组；宽屏浏览时将当前引用目标补充显示在同一列表中，窄屏只显示目标组。Rule 模式显示其他代理组，宽屏进入引用组时仍保留普通组列表。Direct 模式提示普通流量直连，组选择继续保留，不因浏览页面自动切换模式。

## 延迟测试

测速使用受管的本机认证控制 API，让 Mihomo 通过指定候选项访问固定测试目标。默认目标为 `https://www.gstatic.com/generate_204`，单次超时为 5 秒。每轮仅测试当前组，最多同时发起 4 项；不是整份配置的全量测试。DIRECT、REJECT、LoadBalance、Relay 以及无法确定单一出站的引用路径不生成虚构延迟。

单节点重测另有最多 4 项同时运行的队列，可与一组测速并行。重复点击正在等待或测试的同一节点会复用请求；如果该节点已在本组测速队列中，则优先安排已有请求，不重复发起。开始一轮组测速会取消该组的单节点重测，其他组的单节点重测继续。单节点重测只显示卡片内的等待或测试状态，不占用组进度。

延迟区分未测试、等待中、测试中、数值、超时、测试失败与不适用；卡片以 `—` 简写不适用状态，详情保留说明。普通节点可显示已有内核历史样本，但其测试目标不可从历史记录确定，详情明确标注。引用组只展示本次会话中记录了选择路径的测试结果；路径变化后恢复为未测试，避免把旧路径的历史延迟附在新选择旁。某个测试目标失败不能证明节点整体离线。

测速进度只在实际发起测试后显示，完成或用户取消后保留两秒提示再收起；空闲或没有可测试节点时不显示 `已测试 0/0`。测速完成只更新结果，不自动重排候选项。需要重新排序时再次选择延迟排序；已有焦点和选择按成员身份保留。离开页面、执行会改变运行状态的操作或退出时取消正在进行的测试，不延续进度提示；迟到结果不会覆盖新一轮。结果保留在当前会话内存，不额外保存至配置或磁盘。

## 不可用状态

未安装、内核停止、API 不可用、没有代理组和有效空组分别显示。未安装或停止提供相应安装、启动入口；API 错误保留诊断。旧数据不会继续作为可操作的实时列表。

## 代理集合

页头「代理集合 / Proxy providers」展示当前内核加载的 Provider。它与规则页「规则集合」共用 `provider_panel.go` / `provider_panel_view.go` 的状态、更新队列和 Bubbles 输入、viewport 组件，只有读取接口和条目元数据不同。代理集合显示名称、来源类型、节点数量及更新时间；未提供更新时间显示未知，不展示原始节点配置、下载地址或认证字段。

HTTP 集合可更新，File 集合可重新读取；Inline、Compatible 及未知来源只读，也不参与批量更新。「更新全部」最多并发三项，失败可单独重试，关闭面板取消排队与在途请求。面板内保留名称或来源类型搜索、独立滚动和固定操作区；这是集合管理的搜索，代理主列表没有搜索输入。规则页原有集合操作沿用同一组件。

更新通过内核的 `GET /providers/proxies` 与 `PUT /providers/proxies/{name}` 执行，不编辑 Profile、运行 YAML 或服务。完成后自动读取完整快照，使代理组和节点同步；部分更新完成后关闭面板、取消或不确定的失败也重新观察当前内核。类型、请求、Profile、generation 和 PID 的旧结果不能写回新面板或新实例。后端请求不持有应用文件锁，慢下载不阻塞停止服务。接口对应 [Mihomo Provider 路由](https://github.com/MetaCubeX/mihomo/blob/Meta/hub/route/provider.go)。

CLI 的 `nodes`、`select` 继续使用共享应用与 API 用例。TUI 不启动 CLI 子进程，也不改变服务安装或 TUN 的权限边界。
